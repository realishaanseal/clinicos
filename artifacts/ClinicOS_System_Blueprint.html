Rev. 2026-09-17
No diagnosis in the LLM box. llm.ts's SYSTEM_PROMPT records what the doctor said and decided — it does not generate a diagnosis or risk score.
Consent is a 403, not a greyed-out button. Every recording route re-reads consentGiven from the database before accepting audio.
draftJson is write-once. Edits live in workingJson; the diff at signing is the product's accuracy metric.
Audio dies with the signature. The unlink happens inside sign/route.ts, same transaction of intent as writing signedAt.
Middleware is a doorbell, not a lock. It only checks a cookie exists; every route re-derives the real permission via requireApiUser(capability).
Backups use Database.prototype.backup(). A WAL-mode file copy silently drops the newest consultations.

Fig. 1 — Full system map

Every layer, every connection

Client pages compose components, which call hooks, which fetch API routes. Every request — page or API — passes the Edge middleware gate first. Every route handler re-checks identity itself against three capabilities (clinical, frontdesk, admin) before touching the database. Below the API line, everything is a local process: SQLite on disk, a Python ASR sidecar, and Ollama — nothing here can reach the internet with patient data. Solid arrows are calls; dashed arrows are gate checks or return data; thick arrows carry every request through a checkpoint.

Fig. 2 — Mechanism

One consultation, start to signed prescription

The sequence the architecture above exists to support. Consent is checked server-side before any audio byte is accepted; the draft is written once and never touched again; the doctor's edits land in a separate column; the raw audio is unlinked from disk in the same handler that writes the signature.
