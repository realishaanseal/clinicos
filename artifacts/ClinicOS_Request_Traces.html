Storing five seconds of a consultation

POST /api/consults/[id]/audio/chunk?first=1 · maxDuration = 60 · body: raw WebM bytes

The most heavily gated route in the app: six ways to be refused before a single byte is written. useRecorder.ts posts here every five seconds, so all of this runs about twelve times a minute while a visit is being recorded.

In order, on one chunk

StepWhereWhat it does
1src/middleware.tsEdge: cookie exists, then slides its maxAge back to 12 hours
2lib/auth.ts → getCurrentUser()SELECT the session by SHA-256 of the token, joined to its user and clinic
3lib/auth.ts → can()clinical resolves to role === "doctor", nothing else
4lib/db.ts → getConsult()Row fetched with "clinicId" = ? in the WHERE
5lib/clinic.ts → allowRecording()consentGiven short-circuits; otherwise getClinicTerms() + termsInForce(), then setConsent()
6lib/audio-store.ts → appendChunk()Bytes appended; returns { audioPath, total }
7lib/db.tsmarkRecordingStarted() and setAudioPath() on the first slice only

Why the gate is here and not in the UI

A button that is hidden can be posted to anyway. allowRecording() is re-asked on every slice, so revoking the basis stops a recording in progress.

maxDuration = 60

Online this route has a 60-second ceiling and transcription has 300 — the most the host's free plan allows. A long local consultation transcribes in minutes; a hosted one in seconds.

Signing does four things, in this order

POST /api/consults/[id]/sign · body: { note } · requireApiUser("clinical")

Diff, store, delete the audio, log. The order matters: the diff is computed against the untouched draft before anything is written, and the audio is deleted before the row says it was.

What the four steps write

StepTableWritten
1EditOne row per changed field: field, before, after — the accuracy metric, and only for AI-drafted notes
2—The recording is deleted from disk (or its AudioChunk rows removed)
3ConsultfinalJson, signedAt, audioDeletedAt, doctorId, followUpOn; audioPath and workingJson cleared
3bQueueEntrystatus = 'done' for this consult
4AuditEventconsult_sign, with the correction count — never a name

Not in a single transaction

The audio is deleted before the row records it. Getting that order wrong the other way could leave a note claiming the recording is gone while the file is still on disk.

A missing await still compiles

recordAudit(...) without await type-checks, and online the request can end before it runs. Every function in db.ts is async.

A clinic computer pushes what changed

No cookie here. middleware.ts steps aside for /api/sync/* and the route proves the caller itself — seven checks in requireDevice() before a row is looked at.

Same code, both directions

sync.ts runs online to merge what a computer sent, and on the computer to merge what it fetched. One set of rules is the only reason the copies converge.

Add a column, add it here

A new column on a synced table must join COLUMNS in sync.ts or it silently stays on one copy. Nothing fails; the data just never arrives.

Opening a clinic page

GET /patients/<id> · matcher: /((?!_next/static|_next/image|favicon.ico).*)

Two layers, and only the second one decides anything. The Edge layer cannot open the database at all, so it checks the one thing it can and gets out of the way.

can(user, cap), in full

CapabilityThe expressionWho passes
clinicaluser.role === "doctor"doctors only — including the owner-doctor
frontdeskrole === "doctor" || role === "staff"the desk, and the doctor
adminrole === "admin" || user.isAdmina clinic manager, or a doctor who owns the clinic
billingdoctor || staff || admineveryone — whoever is free takes the money. Cancelling needs admin.

Two desks, one token number

addToQueue(clinicId, patientId, addedBy) · src/lib/db.ts

A race SQLite cannot have — its transactions run one at a time — and Postgres can. The same function has to be correct on both, so it retries rather than locking.

Where else this shape appears

startQueueEntry() and createFirstAccount() carry the same retry, for the same reason: two requests reaching Postgres at the same instant.

Why not a lock

Holding a lock across a round trip on a clinic's slow connection would stall the desk. A unique constraint plus a retry costs nothing when there is no contention — which is almost always.
